# Security and trust limits

This local MVP coordinates trusted developers in trusted repositories. It is not an enterprise policy enforcement boundary.

- Provider authentication remains inside the installed official CLIs. AgentBridge does not read or copy credential files, proxy subscriptions or bypass usage limits.
- Execution occurs only on explicit implement/review/test commands. Configured test commands are executable code and run with the operator's privileges. Configuration alone does not launch them. There is no shell interpolation, but a configured shell or a test script can still perform arbitrary actions.
- Worktrees isolate Git changes, not processes, credentials, networks or the filesystem. Use an external sandbox for untrusted code. The Codex adapter requests its native sandbox. Claude receives explicit file tools and no Bash/MCP tools; this is not a claimed OS security boundary. Provider settings, hooks and managed policy can affect behavior.
- Repository text, handoff contents and provider output are untrusted. Prompts label data, review responses are validated, and orchestration transitions happen in application code. Prompt wording alone cannot prevent injection.
- A provider or local process with sufficient filesystem access can edit shared records. Without `setup`, actor names can be spoofed. With `setup`, the clone's actor is the GitHub login reported by the local `gh` session and stored in local Git config: it prevents name collisions and casual impersonation, and agents are refused for acceptance, but the operator can change the config, agents run with the operator's credentials, and records are not signed. `verified-run` denotes a local runner receipt, not a signed external attestation. Human acceptance is explicitly attributed, not authenticated. Commands run inside a detected Claude Code, Codex or `AI_AGENT` session act only as that agent and cannot approve, and every event records the session id and GitHub numeric id. Detection reads environment variables those tools set; it stops agents following instructions and honest mistakes, not an agent that deliberately clears its environment. Approvals (decision and work acceptance, merge resolution, policy changes) are signed with the person's Git SSH signing key when one is configured (`ssh-keygen -Y sign`, namespace `agentbridge-approval`, over a canonical serialization of the event and record id) and verified against the SSH signing keys GitHub lists for the event's numeric GitHub id. A key file without touch can be used by any process running as that user, including an agent; only `-sk` keys, whose signatures carry a user-presence flag that verification requires, show a person was present. `policy signed-approvals required` refuses unsigned approvals and makes `pr publish` fail without a verified acceptance signature. Non-approval events are stamped, not signed.
- Raw output stays in ignored local directories with owner-only files. Shared summaries, test argv, findings, decisions and error descriptions may contain sensitive content; inspect before committing. No automatic redaction guarantee exists.
- Revision binding covers tracked source tree contents and file modes, excluding AgentBridge metadata. Ignored dependencies, environment variables, external services and a malicious mutate-and-restore process are outside this check. Submodules are rejected. Tests passing do not prove absence of defects.
- Output limits, process-group timeouts and cancellation bound normal child execution on POSIX. Abrupt parent termination can leave children running; inspect processes before recovery. No blind replay, no automatic merges of code, no protected-branch writes. The only network publication is the explicit `pr publish` command, which posts a PR comment and commit status through the operator's `gh` session.
- Local locks prevent cooperating processes from overlapping execution. Git controls cross-checkout sharing; with the registered merge driver, record changes merge by ID and one-sided field changes, and same-field disagreements are recorded, reported to Git as conflicts and frozen until a person resolves them. No distributed lock or malicious-writer protection is claimed.

Before enterprise deployment: independent threat review, authenticated and authorized actors, least-privilege execution, trusted receipt issuance, schema validation, artifact retention/redaction, platform qualification and distributed conflict handling.
- In team mode AgentBridge commits and pushes its own `agentbridge-records` branch to `origin` in the background after record changes. It never commits, pushes or merges code branches. Anyone with push access to that branch can write records; signatures on approvals are what make edits detectable (`approvals --verify`). Disable background sync with `git config agentbridge.autoSync false`. A rewritten records history (force push or reset) is detected by every clone that synced before it and refused until a person accepts it. Protect the branch on the host to prevent rewrites in the first place.
